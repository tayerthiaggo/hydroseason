**Architecture:** Keep robust extrema authoritative for seasonal boundaries, add explainable monthly phases as a separate product, and make `analyze_catchment` the routing authority consumed by exports and reports. ## Global Constraints

- Release version is `0.1.0`; no `v0.1.0` tag currently exists and the PyPI project URL currently returns 404.
- `detector="robust_extrema"` remains the default and sole authority for released dynamic annual boundaries.
- Released `phase_model` values are exactly `"none"` and `"rule_based"`; constrained semi-Markov phase labeling is post-`0.1.0` work.
- `phase_model="rule_based"` requires `detector="robust_extrema"`; reject every other detector/phase pairing.
- Changing only `phase_model` must leave every annual hydrological-year value unchanged.
- Regime routing is authoritative: an aseasonal result must have no hydrological-year narrative, rows, spans, peak/trough flags, or phase claims.
- `monthly_condition` and `monthly_phase` remain separate products.
- Core runtime dependencies remain pandas and NumPy only.
- Generated manager reports are light-theme and self-contained; they must not require a CDN or network connection.
- Case-study detection window is `2005-01-01` through `2025-12-01`, inclusive.
- Main study uses whole-catchment `extent_pct`; no heuristic switches between `extent_pct` and `wet_fill_pct`.
- Resolution fidelity compares 30, 60, 90, and 300 metre inputs for all five publish catchments.
- Network/performance tests never run in ordinary CI.
- Do not invent a Zenodo DOI. `CITATION.cff` gains a DOI only after Zenodo has minted it.
- Do not add `.zenodo.json`; Zenodo must read the single metadata source in `CITATION.cff`.

```python
def validate_release_metadata(root, *, expected_tag=None, require_released=False):
    root = Path(root)
    project = tomllib.loads((root / "pyproject.toml").read_text(encoding="utf-8"))["project"]
    version = str(project["version"])
    cff = (root / "CITATION.cff").read_text(encoding="utf-8")
    changelog = (root / "CHANGELOG.md").read_text(encoding="utf-8")
    init = (root / "hydroseason" / "__init__.py").read_text(encoding="utf-8")
    errors = []
    if f'version: "{version}"' not in cff:
        errors.append("CITATION.cff version differs from pyproject.toml")
    if f'__version__ = "{version}"' not in init:
        errors.append("hydroseason.__version__ fallback differs from pyproject.toml")
    if expected_tag is not None and expected_tag != f"v{version}":
        errors.append(f"tag {expected_tag} does not match version {version}")
    if require_released:
        if not re.search(r'^date-released: "\d{4}-\d{2}-\d{2}"$', cff, re.MULTILINE):
            errors.append("CITATION.cff requires date-released for a release")
        if not re.search(rf"^## \[{re.escape(version)}\] - \d{{4}}-\d{{2}}-\d{{2}}$", changelog, re.MULTILINE):
            errors.append(f"CHANGELOG requires a dated [{version}] heading")
    return errors
```

- [ ] **Step 3: Implement deterministic phase boundaries**

For every complete cycle:

1. Label `hy_start` through month before the wet transition as recovery.
2. Compute starting-trough extent from `hy_start - 1 month` and `mid_level = (starting_trough_extent + peak_extent_pct) / 2`.
3. Wet transition is the first usable pre-peak month at or above `mid_level - noise_pp` with non-negative usable-month slope; if absent, use `peak_month`.
4. Label wet transition through `peak_month` as wet.
5. Label month after peak through valid `half_loss_month` as recession; if half-loss is absent, split the post-peak span at its temporal midpoint.
6. Label remaining months through `hy_end` as dry.
7. Preserve positional labels on unusable months but set `phase_status="unusable"` and subtract 0.25 from confidence.
8. Outside complete cycles use `phase="unspecified"` and `phase_status="outside_cycle"`; months belonging to partial rows use `phase_status="unresolved_cycle"`.

Confidence is `0.55 + 0.20` for confirmed boundary, `+0.10` for a real half-loss month, `+0.10` for raw peak selection, minus unusable penalty, clipped to `[0, 1]`.
