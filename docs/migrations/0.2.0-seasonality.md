# Migrating to 0.2.0: mean-monthly seasonality names

HydroSeason 0.2.0 gives the two calendar-month summaries names that describe
what they measure: the maximum and minimum of mean monthly observed extent.
The old `climatological_peak_month` and `climatological_trough_month` names
were deprecated aliases and are now removed from the live Python API and from
`CatchmentAnalysis.summary_row()`.

## Update Python consumers

Replace attribute access on both `WaterRegimeAssessment` and
`CatchmentAnalysis`:

```python
analysis.mean_monthly_peak_month
analysis.mean_monthly_trough_month
```

The values and their null semantics are unchanged. They remain `None` when
the record does not support an identifiable annual timing, and otherwise are
1-based calendar months computed from mean monthly observed extent.

## Update summary consumers

`CatchmentAnalysis.summary_row()` now contains only the canonical keys:

```python
row["mean_monthly_peak_month"]
row["mean_monthly_trough_month"]
```

Code that reads a generated case-study summary should use those same keys.
Previously checked scientific and case-study artifacts are historical records;
their serialized headers are intentionally left unchanged and are not an
indication that the removed aliases remain available in new analyses.

The route name `fixed_climatological_window` is unrelated to these field
names and remains unchanged.
