# 0.2.0 schema addition: trough search geometry diagnostics

This is an **additive schema change with no behaviour change**. The public
decision policy remains `established_0_2_0`. No hydrological-year boundary, no
peak or trough date, and no regime or route changes.

## What was added

Six columns on the diagnostic hydrological-year frame and in
`build_hydro_years_export`: `trough_search_radius_used`,
`boundary_at_search_edge`, `boundary_search_edge_side`,
`outside_window_observed`, `outside_window_lower`, and `retry_outcome`. See
[Export Columns](../report-columns.md) for definitions.

`hydroseason._boundary_geometry.summarise_boundary_geometry` and
`bootstrap_catchment_rate` summarise them per catchment and per cohort.

## What did not change

- The compact CSV bundle. `STABLE_HY_COLUMNS` is unchanged, so downstream code
  reading the default CSVs sees no new columns.
- Every boundary date, cycle length, regime, and route.
- `ESTABLISHED_POLICY`, which remains `established_0_2_0`.

## Why it was added

The trough search radius, the adaptive retry radius, and the relaxed minimum
cycle coverage were inherited from the first dynamic-year implementation and
have never been selected against truth. They appear in no calibration grid and
in no fingerprint. These diagnostics are the instrument that makes that
selection measurable; the selection itself is specified in
[Decision Policy 0.3.0 Design](../decision-policy-0.3.0.md) and has not run yet.

## Downstream impact

Code that enumerates diagnostic hydrological-year columns positionally, or
asserts an exact column count on `build_hydro_years_export`, needs updating.
Code reading columns by name is unaffected.
