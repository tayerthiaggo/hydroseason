# hydroseason-v0.3.0 on the Fitzroy tiles: results

Date: 2026-11-05. Branch `method-v0.3.0`. A before/after check, not a decision test.

The tiles are HydroChannel's ~46 km blocks over the whole Fitzroy, as hydropools uses them; each series is the channel-zone monthly extent inside one tile. hydropools' clock-anchor analysis (`hydropools/docs/handoff/2026-10-30-clock-anchor-analysis.md`) found many tile-years failing there: a tile-year fails when its trough is unresolved or its amplitude-to-floor ratio is below 3. This check reruns every tile under both methods.

Script [`scripts/v030_fitzroy_tiles.py`](../../scripts/v030_fitzroy_tiles.py); outputs [2026-11-05-v0.3.0-fitzroy-tiles.json](2026-11-05-v0.3.0-fitzroy-tiles.json) and [the identity check](2026-11-05-v0.3.0-fitzroy-tiles-identity.json). Run directories and per-tile-year table: `data_local/intermediate/hydroseason_v030_fitzroy_tiles/`.

## Inputs

- **Production**: `hydropools/work/fitzroy_v3/hydroseason/<tile>/channel_monthly_extent.csv`, 40 tiles, percentages only. This is what the hydropools pipeline runs.
- **Counts**: `hydropools/work/u1/fitzroy/tiles_e/<tile>/series.csv`, 41 tiles, with pixel counts over intermittent pixels (hydropools' U1 inputs).

Both libraries ran `run_hydroseason` with default options. 0 errors in 162 runs.

**Identity.** The 0.2.0 rerun reproduces hydropools' stored production run on all 40 tiles, on every column both have. Later 0.2.0 commits added five export columns (`status_reason`, `trough_refinement_status`, `trough_refinement_reason`, `baseline_eligible`, `baseline_n`).

- **0.3.0 rescues no failing tile-year.** The gates and boundaries are unchanged, so a failing year stays failing. The trough-label fix can only make a label less precise, which adds 4 (production) and 5 (counts) failing years. The tiles with the most failing years (production 13, 39, 31, 42, 56) are unchanged apart from condition labels.
- **The trough-label fix fires on the healthier tiles**, where `point` troughs are common, not on the failing ones.
- **hydropools' end-dry clock** (`trough_date` if `point`, else the interval end, else the boundary) barely moves. A widened `point` trough loses `trough_date`, but its interval now ends at the boundary, which was the old `trough_date`. The clock moves only where an `interval` or `broad` label ended before the boundary: tile07 in 1996 moves from June to November (both sets), and tile03 in 2010 (counts) from September to January.
- **Condition labels** reach 30 of 40 production tiles; the 10 without labels are mostly the failing tiles. hydropools sizes wets with its own era rule, not with HydroSeason's condition labels.
- **Nothing else differs**: routes, boundaries, dates, peaks, ratios, events and low-extent spells are identical.

## Monthly phases change with timing

Not listed in the 0.3.0 proposal, and not seen on the five case studies, where no trough label changed. Monthly phases follow the cycle's aggregate timing under the existing phase rules:
- where `timing_status` goes from `point` to `interval`, `phase_status` changes (for example `provisional` to `interval_boundary`) and the phase stays;
- where it becomes `unresolved`, the year has no rising or receding months (`phase` `unspecified`, `phase_status` `unresolved_cycle`).

Every monthly change sits in a year whose timing label changed. The report shows the same change: the end-dry marker is drawn as an interval, and the extent hover text names the new phase; extent values are unchanged. The methods reference and CHANGELOG now say so.
